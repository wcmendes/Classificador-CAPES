## About

NoQualis is a Zotero plugin that classifies journal articles and conference papers according to CAPES evaluation criteria for the 2025-2028 quadrennium. It consumes pre-computed snapshots generated by an offline Python pipeline and displays classification verdicts directly in Zotero's item list.

The system is composed of two independent packages in a monorepo:

- **`pipeline/`** (Python): ingests bibliometric sources, normalizes data, runs a declarative rule engine, and generates immutable snapshots.
- **`plugin/`** (Zotero 7, JavaScript): loads snapshots locally and presents verdicts in Zotero's UI — columns, detail panel, and batch tagging.

### Why NoQualis

Brazilian graduate programs are evaluated by CAPES using bibliometric criteria that vary by Area. Researchers need to know how their publication venues rank **before** submitting, but the official classification is only published after the evaluation cycle ends.

NoQualis bridges this gap by:

- Automating the rules published in each Area's evaluation ficha
- Producing conservative estimates when data is incomplete (never overestimates)
- Working fully offline — no API calls, no cloud dependency
- Growing incrementally: starts with zero sources, adds one at a time without breaking

## Features

| Feature | Description |
|---------|-------------|
| **Declarative rules** | All classification logic lives in JSON files (`areas/*.json`), not code |
| **Immutable snapshots** | Versioned by date — reproducible verdicts at any point in time |
| **Zotero columns** | Displays stratum (A1–A8) and status directly in the item list |
| **Detail panel** | Full decision trail: which metric, which source, which rule fired |
| **Batch tagging** | Tag selected items with their classification for filtering |
| **Multi-area** | Switch between evaluation areas; each has its own ruleset |
| **Conservative degradation** | Partial data produces estimates that never overestimate the stratum |
| **Onboarding CLI** | `pipeline/onboard.py` guides you through adding new sources |

## How it works

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐    ┌────────┐
│  External    │    │   Pipeline   │    │  Immutable   │    │  Zotero  │    │ Zotero │
│  Sources     │───▶│  (Python)    │───▶│  Snapshot    │───▶│  Plugin  │───▶│   UI   │
│              │    │              │    │  (JSON)      │    │  (JS)    │    │        │
│ SJR, Scopus, │    │ parse →      │    │ area02-      │    │ lookup   │    │columns │
│ JCR, ABDC,   │    │ normalize →  │    │ 2026-07.json │    │ by ISSN  │    │panel   │
│ Qualis hist. │    │ classify →   │    │              │    │          │    │tags    │
│              │    │ snapshot     │    │              │    │          │    │        │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────┘    └────────┘
```

> ⚠️ **This project is NOT official.** It is not affiliated with CAPES, MEC, or any governmental body. The classifier reproduces rules published in evaluation fichas and the referential for the new Qualis, but has no institutional connection. In case of divergence between this tool's output and the official ficha on Plataforma Sucupira, the official ficha prevails. The verdict displayed by the plugin is an automated estimate and does not replace consultation of the official classification system.

## Installation

1. Download `noqualis.xpi` from [Releases](https://github.com/wcmendes/NoQualis_Zotero/releases)
2. In Zotero: **Tools → Add-ons → ⚙️ → Install Add-on From File**
3. Select the `.xpi` file
4. Configure the snapshot directory in **Edit → Preferences → NoQualis**
5. Place snapshot files (e.g., `area02-2026-07.json`) in the configured directory

## Contributing an Area

1. Locate the official evaluation ficha for the desired area on the [CAPES website](https://www.gov.br/capes/pt-br/acesso-a-informacao/acoes-e-programas/avaliacao/sobre-a-avaliacao/areas-avaliacao)
2. Create `areas/areaXX-nome.json` following `schema/area.schema.json`
3. Declare the metrics needed in the `operandos` and rule conditions
4. Register any new sources in `sources.yml` with `status: pendente`
5. Write tests in `pipeline/tests/test_areaXX.py` using synthetic fixtures
6. Run `pytest` to validate the rules fire correctly
7. Open a Pull Request with the ficha PDF in `docs/fontes/` for reference

## Português

### Sobre

NoQualis é um plugin para Zotero que classifica artigos de periódicos e trabalhos em eventos segundo os critérios de avaliação CAPES para o quadriênio 2025-2028. O sistema consome snapshots pré-calculados por um pipeline Python offline e exibe os vereditos de classificação diretamente na interface do Zotero.

O sistema é composto por dois pacotes independentes em um monorepo:

- **`pipeline/`** (Python): ingestão de fontes bibliométricas, normalização, motor de regras declarativo e geração de snapshots imutáveis.
- **`plugin/`** (Zotero 7, JavaScript): carrega snapshots locais e apresenta vereditos na interface — colunas, painel de detalhes e tagging em lote.

#### Por que NoQualis

Programas de pós-graduação brasileiros são avaliados pela CAPES com critérios bibliométricos que variam por Área. Pesquisadores precisam saber como seus veículos de publicação são classificados **antes** de submeter, mas a classificação oficial só é publicada ao final do ciclo avaliativo.

NoQualis preenche essa lacuna:

- Automatiza as regras publicadas na ficha de avaliação de cada Área
- Produz estimativas conservadoras quando dados estão incompletos (nunca superestima)
- Funciona completamente offline — sem chamadas de API, sem dependência de nuvem
- Cresce incrementalmente: nasce com zero fontes, adiciona uma por vez sem quebrar

> ⚠️ **Este projeto NÃO é oficial.** Não possui vínculo com a CAPES, MEC ou qualquer órgão governamental. O classificador reproduz as regras publicadas nas fichas de avaliação e no referencial para o novo Qualis, porém não possui vínculo institucional. Em caso de divergência entre o resultado desta ferramenta e a ficha oficial na Plataforma Sucupira, a ficha oficial prevalece. O veredito exibido pelo plugin é uma estimativa automatizada e não substitui a consulta ao sistema oficial de classificação.

### Funcionalidades

| Funcionalidade | Descrição |
|---------------|-----------|
| **Regras declarativas** | Toda lógica de classificação vive em arquivos JSON (`areas/*.json`), não em código |
| **Snapshots imutáveis** | Versionados por data — vereditos reproduzíveis em qualquer ponto no tempo |
| **Colunas no Zotero** | Exibe estrato (A1–A8) e estado diretamente na lista de itens |
| **Painel de detalhes** | Trilha de decisão completa: qual métrica, qual fonte, qual regra disparou |
| **Tagging em lote** | Marca itens selecionados com sua classificação para filtragem |
| **Multi-área** | Alterne entre áreas de avaliação; cada uma tem seu próprio conjunto de regras |
| **Degradação conservadora** | Dados parciais produzem estimativas que nunca superestimam o estrato |

### Instalação

1. Baixe `noqualis.xpi` da página de [Releases](https://github.com/wcmendes/NoQualis_Zotero/releases)
2. No Zotero: **Ferramentas → Complementos → ⚙️ → Instalar complemento a partir de arquivo**
3. Selecione o arquivo `.xpi`
4. Configure o diretório de snapshots em **Editar → Preferências → NoQualis**
5. Coloque os arquivos de snapshot (ex: `area02-2026-07.json`) no diretório configurado

### Contribuindo com uma área

1. Localize a ficha de avaliação oficial da área desejada no [site da CAPES](https://www.gov.br/capes/pt-br/acesso-a-informacao/acoes-e-programas/avaliacao/sobre-a-avaliacao/areas-avaliacao)
2. Crie `areas/areaXX-nome.json` seguindo o `schema/area.schema.json`
3. Declare as métricas necessárias nos `operandos` e condições das regras
4. Registre novas fontes em `sources.yml` com `status: pendente`
5. Escreva testes em `pipeline/tests/test_areaXX.py` usando fixtures sintéticas
6. Execute `pytest` para validar que as regras disparam corretamente
7. Abra um Pull Request com o PDF da ficha em `docs/fontes/` como referência
